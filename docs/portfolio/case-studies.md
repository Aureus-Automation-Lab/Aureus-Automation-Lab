# Pro-Tier Public Case Studies

These are public-safe case studies for the main Aureus Automation Lab project lines.

They are written for buyers, recruiters, partners, and technical reviewers who need to understand the value without seeing private implementation.

They are not customer testimonials, production-results claims, private workflow exports, or ROI proof. They show the system shape, buyer problem, AI role, review boundary, evidence model, and commercial next step.

## How To Read These

Each case study follows the same review pattern:

```text
Buyer problem
-> System shape
-> AI role
-> Human review boundary
-> Evidence / proof
-> Business output
-> Offer path
```

## 01. Automation Audit

### Buyer Problem

A company knows work is too manual, but the first useful automation is unclear.

The risk is starting with a tool before understanding the process: the team automates a broken handoff, misses the approval boundary, or builds something nobody can operate later.

### System Shape

```text
process intake
-> workflow map
-> friction points
-> automation candidates
-> review boundaries
-> first useful build recommendation
```

### AI Role

AI can help summarize the process, cluster repeated steps, draft interview questions, and prepare candidate automation opportunities.

### Human Review Boundary

The owner still decides which process matters, which actions are sensitive, which users are affected, and what the first useful version should be.

### Evidence / Proof

Public-safe proof can include a process map, risk list, review-boundary table, and first-scope recommendation.

### Business Output

The company leaves with a clear first build direction instead of a vague "we should automate more" idea.

### Offer Path

**Automation Audit -> scoped workflow build -> validation / handoff -> monthly partner if useful.**

### What Stays Private

Private process details, internal documents, employee names, customer data, credentials, production systems, and financial data stay private.

## 02. n8n Workflow Review

### Buyer Problem

An existing automation runs, but nobody trusts it when something changes.

Common symptoms:

- no clear owner,
- weak naming,
- unclear failure handling,
- no retry or fallback path,
- unknown credential boundaries,
- no handoff notes.

### System Shape

```text
workflow inventory
-> intent review
-> risk scan
-> failure path
-> validation checklist
-> improvement plan
```

### AI Role

AI can summarize workflow intent, identify documentation gaps, propose test cases, and draft review questions.

### Human Review Boundary

No live activation, credential change, external send, production import, or destructive action happens without explicit approval.

### Evidence / Proof

Public-safe proof can include a sanitized review checklist, state map, failure-path model, and handoff note.

### Business Output

The workflow becomes easier to understand, repair, explain, and improve.

### Offer Path

**n8n Workflow Review -> cleanup plan -> rebuild or monthly automation support.**

### What Stays Private

Raw workflow exports, workflow IDs, webhook paths, credentials, runtime logs, private node details, and production settings stay private.

## 03. n8n Workflow Automation Build

### Buyer Problem

A repeated business process is still handled manually or through disconnected tools.

The business needs automation, but it also needs review, state, failure handling, and handoff.

### System Shape

```text
business trigger
-> structured input
-> workflow logic
-> AI-assisted step
-> review gate
-> controlled action
-> evidence note
-> handoff
```

### AI Role

AI may classify, extract, summarize, draft, or suggest the next step.

### Human Review Boundary

Sensitive actions stay human-approved: external messages, public claims, finance handoffs, production actions, and client-facing deliverables.

### Evidence / Proof

Public-safe proof can include an architecture diagram, input/output contract, validation checklist, and proof-note example.

### Business Output

The team gets a workflow that is designed as a system, not a hidden script.

### Offer Path

**Automation Audit or n8n Review -> Workflow Automation Build -> validation and operating handoff.**

### What Stays Private

Private exports, secrets, real payloads, endpoints, workflow IDs, and production logs stay private.

-> daily report

### What Stays Private

Lead lists, inbox data, message drafts, prompts, workflow IDs, contact data, and private execution logs stay private.

## 05. FinEcon Pocket / Bridge

### Buyer Problem

Invoices and documents arrive in messy places: email, folders, chats, Drive, paper scans, or memory.

The owner needs to know what arrived, what was extracted, what is uncertain, what needs review, and what can move downstream.

### System Shape

```text
Pocket intake
-> n8n finance/document backend
-> structured extraction
-> validation checks
-> review decision
-> bridge readiness
-> reviewed handoff
-> proof notes
-> accountant validation boundary
```

### AI Role

AI may extract candidate fields, classify document type, summarize missing context, flag uncertainty, and prepare review notes.

### Human Review Boundary

Accounting-sensitive conclusions, downstream import decisions, cleanup decisions, VAT/control-statement/predkontacia confirmation, and final official treatment remain subject to owner/accountant review.

### Evidence / Proof

Public proof lives in the [FinEcon proof package](../../public-proof/finecon/README.md) and [FinEcon source-backed status](../proof/finecon-source-backed-status.md).

Publicly, the right claim is:

```text
FinEcon has source-backed Pocket, bridge, proof, and preflight architecture.
Accounting correctness remains pending accountant validation.
```

### Business Output

The buyer gets a clearer document-to-review-to-handoff path instead of scattered document handling.

### Offer Path

**FinEcon Paid Pilot -> accountant-reviewed validation -> client demo flow -> controlled rollout decision.**

### What Stays Private

Real invoices, company records, POHODA access details, internal routes, workflow exports, document identifiers, runtime logs, proof-pack file locations, credentials, and private screenshots stay private.

### System Shape

```text

-> scope and rules
-> AI prepares work
-> reviewable delivery
-> validation
-> approval gate
-> evidence
-> handoff
```

### AI Role

AI can draft, summarize, classify, plan, check, propose changes, and prepare review material.

### Human Review Boundary

Public claims, finance handoffs, production actions, client-facing outputs, external messages, and live changes need approval.

### Evidence / Proof

Public proof lives in the [Aureus OS proof package](../../public-proof/aureus-os/README.md): operating model, action gates, and buyer example.

### Business Output

The company gets a way to use AI without losing control of ownership, review, validation, and evidence.

### Offer Path

**Aureus OS Setup -> routines / scorecards -> monthly operating partner if useful.**

### What Stays Private

Internal prompts, private repositories, production context, client-like data, logs, credentials, and internal operating state stay private.

## 09. Monthly Automation Partner

### Buyer Problem

Automations are not one-time objects. They age as the business changes.

Without a maintenance rhythm, workflows lose context, fail quietly, or no longer match the process.

### System Shape

```text
monthly review
-> issue log
-> improvement backlog
-> priority decision
-> safe change
-> validation
-> evidence note
-> handoff
```

### AI Role

AI can summarize incidents, draft backlog items, compare changes, generate validation checklists, and prepare review packets.

### Human Review Boundary

Priorities, live actions, budget changes, production changes, external messages, and business-critical decisions remain owner-approved.

### Evidence / Proof

Public-safe proof can include a monthly review template, risk log, validation record, and handoff note.

### Business Output

Automation becomes a managed operating system instead of a pile of one-off scripts.

### Offer Path

**Automation Audit or paid pilot -> monthly automation partner.**

### What Stays Private

Private tickets, production logs, client data, credentials, budget details, runtime records, and internal system access stay private.
