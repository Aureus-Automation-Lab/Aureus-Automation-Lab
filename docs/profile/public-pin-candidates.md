## Pin Rules

- Do not pin private repos expecting public reviewers to see them.
- Do not pin unfinished or confusing repos without a README and status note.
- Do not pin raw workflow exports, credentials, internal config, private screenshots, or client-like data.
- Internal repos can be used in controlled walkthroughs when access and privacy boundaries are clear.
- Public pins should form a coherent story: profile, architecture, automation, invoice workflow, visual product surface, and small proof/template.

## Public-Safe Gap

If no public-safe implementation repo exists yet, create a sanitized demo repo or gist instead of exposing private repositories.
