# GitHub Pinned Items Strategy

Pins should communicate the Aureus system in under ten seconds. GitHub supports up to six pinned repositories or gists; fewer, stronger items are preferable.

## Target Story

```text
identity
→ operating system
→ full-stack product
→ finance workflow
→ risk-first infrastructure
→ small reusable engineering proof
```

## Recommended Order

| Priority | Public artifact | Purpose |
| --- | --- | --- |
| 1 | `Aureus-Automation-Lab/Aureus-Automation-Lab` | Main identity, project map, evidence index, and review paths |
| 2 | Aureus CRM Operations proof repo or gist | Strongest accessible full-stack business-product proof |
| 3 | Aureus OS architecture proof repo or gist | Shows mission control, autonomy boundaries, validation, and evidence |
| 4 | Aureus FinEcon proof repo or gist | Shows domain workflow and professional-review boundaries |
| 5 | Aureus Trading Infrastructure proof repo or gist | Shows observability, CI controls, and paper-run constraints without strategy disclosure |
| 6 | Polished reusable validator or template | Shows concise implementation and documentation quality |

## Current Safe State

Only the profile repository is currently ready to pin as a public repository. The remaining entries should be created from the sanitized packages under [public-proof](../../public-proof/README.md) after separate publication review.

Do not pin private repositories, raw workflow exports, incomplete experiments, client-like data, credentials, endpoints, private screenshots, or unsupported outcome claims.

## Acceptance Standard For Every Future Pin

- understandable README in under one minute,
- one clear architecture or workflow visual,
- status and limitation section,
- reproducible validation where applicable,
- no secret or privacy finding,
- signed-out browser review,
- consistent Aureus naming and description under the [Public Naming System](../portfolio/naming-system.md).
