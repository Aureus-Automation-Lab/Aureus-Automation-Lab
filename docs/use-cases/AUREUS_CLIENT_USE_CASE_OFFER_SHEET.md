# Aureus Client Use Case Offer Sheet

Start with **Automation Audit**.

It is the safest first purchase because it maps the real process before a workflow is built.

```text
AI prepares. People approve. Evidence remains.
```

## Six Use Cases

| Use case | Buyer problem | What client receives | Best first step |
| --- | --- | --- | --- |
| Automation Audit | Work is manual, but the first useful automation is unclear. | Process map, automation candidates, review boundary, risk list, pilot brief. | Send one repeated process. |
| n8n Workflow Review + Build | A workflow runs, but it is fragile or hard to explain. | Workflow review, failure map, validation checklist, repair/build direction, handoff notes. | Share a sanitized workflow description. |
| FinEcon Pocket / Bridge | Documents enter through messy channels and handoff is hard to inspect. | Intake path, review queue direction, POHODA handoff model, proof pack, exception list, accountant checklist. | Choose one document flow. |
| Approval-Safe Sales Machine | Leads and follow-ups depend on memory and inconsistent messaging. | Lead state model, approved-message workflow, reply handling direction, reporting. | Start with one lead source and one approved offer. |
| Aureus OS / AOP | AI work is scattered across chats, docs, tools, and workflows. | Operating model, approval gates, validation, evidence format, handoff model. | Pick one area where AI should help but not decide alone. |
| Public Proof Website + Automation | The public offer is unclear and disconnected from operations. | Offer structure, website copy direction, intake path, follow-up workflow, public-claim checklist. | Send offer, buyer, and key client question. |

## What We Do Not Claim

This offer sheet does not claim customer results, production rollout, accounting correctness, tax/legal advice, security certification, promised revenue, or broad market adoption.

FinEcon does not replace accountants. Sensitive decisions remain reviewed.

## Suggested Pilot Path

```text
Automation Audit
-> scoped pilot
-> controlled build / proof
-> review and handoff
-> next decision
```
