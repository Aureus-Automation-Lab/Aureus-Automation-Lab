The answer should be visible:

- the offers are connected to documented packages,

- the automation work is connected to n8n workflow standards,

- LinkedIn and growth content are designed to come from Git truth,
- proof and public/private boundaries are explicit.

## Public-Safe Boundaries

The profile may show:

- positioning,
- offer structure,
- architecture maps,
- sanitized proof direction,
- process standards,
- quality gates,
- public pages,
- visual concepts,
- public-safe capability descriptions.

The profile must not show:

- secrets,
- credentials,
- tokens,
- webhook URLs,
- private workflow IDs,
- private client records,
- raw POHODA payloads,
- private screenshots,
- production settings,
- unsupported results,
- fake testimonials,
- unapproved financial or accounting claims.

## How To Use This Page

Use this map before publishing, sending the profile to a prospect, or creating a LinkedIn post from Git.

If a public claim is not connected to a source artifact, proof pack, validation note, or owner-approved result, rewrite it as a direction or capability instead of a proven outcome.
