# Security Policy

## Reporting a vulnerability

Please do not open a public issue with a vulnerability report, exploit details, access information, customer data, or reproduction material from an operating environment.

Use GitHub private vulnerability reporting when it is enabled for this repository. If that option is unavailable, open a minimal public issue titled `Security contact requested` with no vulnerability detail. A maintainer will provide a private reporting path.

Use synthetic examples in any follow-up material unless a maintainer explicitly requests otherwise through the private channel.

## Scope

This repository is a public portfolio and documentation surface. Reports may concern the public repository, its published assets, documentation, and validation scripts. Do not use it to disclose details of private client systems, credentials, internal automation, or live operating environments.

## What to include privately

When a private reporting path is available, include a concise description, affected public file or component, safe reproduction steps, impact, and any suggested mitigation. Do not include credentials or personal data.

## Response approach

Maintainers will acknowledge reports when a private channel is available, assess the public-repository impact, and coordinate a safe fix. No response-time or disclosure timetable is promised; the appropriate timing depends on the report and the affected material.
