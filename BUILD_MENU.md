# Build Menu

This is a public-safe menu of collaboration formats. It is not a fixed product catalog. The right scope depends on the process, risk, tools, and owner review path.

## 1. Automation Clarity Sprint

Best when a team knows something is manual or messy, but the first useful build is not clear yet.

Typical outputs:

- process map,
- automation candidates,
- risk and review points,
- first-slice recommendation,
- acceptance criteria.

Good result:

The team knows what to build first, what to avoid, and how to validate the first version.

## 2. Internal Tool Slice

Best when a team needs a lightweight interface for operating work.

Typical outputs:

- dashboard or control surface concept,
- core workflow states,
- admin or review flow,
- handoff notes,
- next-build backlog.

Good result:

The team can see and operate the work from one clearer place.

## 3. AI-Assisted Workflow

Best when AI can speed up drafting, classification, research, review, or content operations, but final ownership must remain clear.

Typical outputs:

- assistant role definition,
- input and output format,
- confidence or review states,
- human approval boundary,
- evaluation examples.

Good result:

AI helps the workflow without hiding decisions or removing owner review.

## 4. Document And Data Flow

Best when a process depends on structured intake, documents, records, or repetitive data review.

Typical outputs:

- intake model,
- classification or extraction outline,
- validation checklist,
- exception handling,
- review and handoff flow.

Good result:

The team can move from raw inputs to reviewed outputs with fewer manual gaps.

## 5. Product Prototype

Best when a founder, partner, or internal team needs to make an idea tangible quickly.

Typical outputs:

- user journey,
- interface slice,
- demo narrative,
- feedback questions,
- next-build plan.

Good result:

The idea becomes concrete enough to test, explain, and improve.

## What Stays Explicit

Every good scope should make these clear:

- owner,
- user outcome,
- first useful version,
- review boundary,
- sensitive data boundary,
- validation path,
- handoff owner.
